# Neural City — Yelahanka Digital Twin Demo

An interactive React/Three.js dashboard for exploring OpenStreetMap building and road geometry for Yelahanka, Bengaluru. It is an initial digital-twin visualization milestone, not a production city-operations platform.

## Run locally

Start the API and frontend in separate terminals:

```sh
npm run dev:api
```

```sh
npm run dev
```

The Vite development server proxies `/api` requests to the local API on port `3001`. For a production frontend bundle, run `npm run build`; `npm run lint` checks the project sources; `npm run test:api` runs the API and simulation tests.

## Demo features

- 3D GIS view with toggles for building footprints, roads, illustrative risk zones, virtual sensor nodes, and schematic utility routes.
- Pausable five-second synthetic telemetry updates delivered over Server-Sent Events (SSE) by the local Node API.
- Shared scenario and pause/resume controls sent to the API, with validated JSON responses and visible reconnect errors.
- Emergency routes calculated over the local OSM road graph and drawn on the 3D map; the road-closure scenario computes a detour.
- What-if presets for baseline operations, heavy rainfall, road closure, drainage upgrades, and signal retiming.
- A simulated time-series outlook, sample emergency corridors, and scenario-dependent response recommendations.

The GeoJSON map geometry is local project data. The API exposes `GET /api/health`, `GET /api/twin/snapshot`, `GET /api/twin/stream`, `GET /api/twin/routes`, `POST /api/twin/scenario`, and `POST /api/twin/control`. Routes are computed from the OSM road graph using assumed speeds by road class. The source does not include one-way restrictions or live traffic, so routes are bidirectional estimates rather than dispatch-grade directions. The closure scenario blocks one segment of each baseline route to demonstrate detouring.

Sensor readings and the telemetry stream are generated by the local simulation; they are not connected to physical devices. Risk areas, utility routes, forecast values, and response plans are also illustrative. Preparing a response plan does not dispatch teams.

## Production integration gaps

- Replace the simulated API source with a secure real-time ingestion pipeline for authenticated IoT feeds; do not put device credentials in the browser.
- Connect georeferenced utility assets, terrain, drainage capacity, rainfall, and traffic observations.
- Replace deterministic demo projections with evaluated forecasting and graph-learning services, with model versioning and uncertainty reporting.
- Integrate validated routing, simulation, identity/access control, and dispatch services before using recommendations operationally.
